# Vermintide 2 PVP Mod 實作計畫

## 概述

本計畫旨在為《鼠疫2》建立一個 PVP Mod，盡量複用原本遊戲的現有機制，並在必要時以 Hook 的方式擴展功能。Mod 將放置於 `d:\frank\gemini\PVP\` 目錄下。

---

## 技術背景分析

以下是從原始碼中提取的關鍵機制：

### 傷害系統
- **友軍傷害**：位於 `scripts/helpers/damage_utils.lua`，函數 `do_damage_calculation()`（L119）。當 `is_friendly_fire = true` 時，傷害乘以 `friendly_fire_multiplier`。
- **近戰命中判斷**：`action_sweep.lua` 第 889 行：`local is_friendly_fire = not enemy_units_lookup[hit_unit]`，第 897 行直接以 `not is_friendly_fire` 跳過友軍傷害。**我們需要 Hook 此處讓玩家之間可以互相傷害。**
- **`DamageUtils.allow_friendly_fire_melee()`**（L2923）：`difficulty_settings.friendly_fire_melee` 控制近戰友軍傷害。

### 格擋系統
- **格擋判斷**：`generic_status_extension.lua`，`can_block()` 函數（L550-604）：計算攻擊者方向與玩家朝向之夾角，對比武器的 `block_angle`，決定是否可格擋。
- **格擋消耗**：`add_fatigue_points()` 函數（L772）。`blocked_attack = 1`、`blocked_sv_sweep = 4`、`blocked_sv_cleave = 16`（`player_unit_status_settings.lua`）。
- **完美格擋**：`action_block.lua` L45 設置 `timed_block = t + 0.5`；`action_melee_start.lua` L65 同樣設置（蓄力時）。命中時在 `blocked_attack()` 函數（L624）判斷 `is_timed_block`，若是完美格擋則 `fatigue_cost` 透過 `timed_block_cost` buff 乘算（可歸零）。

### 格擋角度
- **`can_block()` 函數**：`block_angle`（通常 90°）為內圈角，`outer_block_angle`（360°）為外圈角。外圈格擋的 `fatigue_point_costs_multiplier = 2`。
- **原遊戲角度外不格擋**：原本角度外直接 `return false`，但對 AI 敵人而言不會傷害，因為 `check_melee_block()` 的回傳值判斷整個攻擊流程。對玩家而言，需要讓角度外的攻擊直接命中（原本已是如此，因為 can_block 回傳 false 後不會觸發格擋）。

### 踉蹌 (Stagger/Overpowered)
- **Overpowered 狀態**：`StatusUtils.set_overpowered_network(unit, true, template_name, attacking_unit)` 觸發，玩家進入 `player_character_state_overpowered.lua` 狀態。
- **Overpowered 模板**：`PlayerUnitMovementSettings.overpowered_templates` 定義動畫與行為。
- **推擊踉蹌**：`action_push_stagger.lua` 推擊對敵人生效，但原本跳過友軍（`is_enemy` 判斷在 L186-190）。

### 攻擊階段
- **`melee_start` 階段（續力/蓄力）**：由 `ActionMeleeStart`（`action_melee_start.lua`）處理，`ActionUtils.is_melee_start_sub_action()` 判斷。可被命中打斷（L1238 的 `uninterruptible_heavy` 邏輯）。
- **`sweep` 揮舞階段**：`ActionSweep`（`action_sweep.lua`），有 `uninterruptible` 設置時不可打斷。
- **打斷邏輯**：`player_character_state_helper.lua` L1238：`can_interrupt = (not current_action_settings.uninterruptible and ...)`。

### 武器碰撞（需新增）
- 原遊戲**不存在玩家之間的武器碰撞**，需完全自訂實作。
- 思路：在 `action_sweep.lua` 的掃描命中時，若目標也在攻擊中，則觸發「卡刀」效果，而非傷害。

---

## 開放問題

> [!IMPORTANT]
> **Mod 框架**：此 Mod 採用哪個 Mod 框架？Vermintide Mod Framework (VMF) 是標準選項，需確認是否使用。計畫假設使用 VMF 的 `mod:hook()` 機制。

> [!IMPORTANT]
> **天劫難度的友軍傷害乘數**：「天劫難度的友軍傷害計算方式」指的是 Cataclysm 難度的 `friendly_fire_multiplier`。實際數值需從難度設定表確認，或使用固定值（如 0.5）。請確認要使用哪個難度的友軍傷害乘數，或設定一個固定的 PVP 傷害比例。

> [!IMPORTANT]
> **雙手武器判斷標準**：「雙手武器的重擊」如何判斷？是根據武器模板的某個欄位（如 `two_handed`），還是根據武器分類（如 2h_sword、greatsword 等）？

> [!NOTE]
> **網路同步**：PVP 傷害的網路同步是否需要特別處理？原遊戲有完整的 RPC 機制，Hook 後應可複用。

## 修改計畫

### 系統 1：PVP 傷害核心（近戰攻擊命中友軍）

#### [MODIFY] `action_sweep.lua` → Hook `_do_overlap`
- 在計算命中目標時（L897），移除 `not is_friendly_fire` 的限制。
- 對友軍玩家目標：改以 `is_friendly_fire = true` 方式走正常傷害流程，讓 `do_damage_calculation` 套用友軍傷害乘數。
- 同時呼叫 `DamageUtils.check_melee_block()` 判斷格擋。

#### [MODIFY] `action_push_stagger.lua` → Hook 推擊邏輯
- 在 L186-190 中，移除 `is_enemy` 限制，讓推擊可以作用於其他玩家。
- 推擊後對目標玩家觸發 1 秒踉蹌（`set_overpowered_network`）。

---

### 系統 2：格擋互動

#### 原本機制（直接複用）
- `can_block()` → 格擋角度判斷（已有效）
- `blocked_attack()` → 消耗體力
- `add_fatigue_points()` → 計算體力消耗

#### PVP 格擋體力消耗對應
| 攻擊類型 | 對應的 fatigue_type | 原本數值 |
|---------|-------------------|--------|
| 玩家輕擊 | `blocked_attack` | 1 點 |
| 單手武器重擊 | `blocked_sv_sweep` | 4 點 |
| 雙手武器重擊 | `blocked_sv_cleave` | 16 點 |

**完美格擋**（原 `timed_block_cost` 天賦）：完全複用，無需修改。

---

### 系統 3：完美格擋/推擊踉蹌（新增）

#### [NEW] `pvp_stagger.lua`
- 當 `is_timed_block = true` 時（完美格擋），對攻擊者觸發 3 秒踉蹌。
- 當推擊命中玩家時，觸發 1 秒踉蹌。
- 踉蹌使用 `StatusUtils.set_overpowered_network()`。
- **防疊加**：連續推擊踉蹌時間若仍有效，不延長（最多 1 秒）。
- 踉蹌期間玩家無法進行格擋（因為 `overpowered` 狀態會停止武器動作）。

**所需 Overpowered 模板**（新增）：
```lua
-- 3 秒完美格擋踉蹌
pvp_parry_stagger = { duration = 3, ... }
-- 1 秒推擊踉蹌  
pvp_push_stagger = { duration = 1, ... }
```

---

### 系統 4：武器碰撞卡刀（新增）

#### [NEW] `pvp_weapon_clash.lua`
實作邏輯：在 `action_sweep.lua` 的命中處理中，在確認傷害之前，額外檢查目標玩家是否也正在進行攻擊（`current_action_settings.kind == "sweep"` 或 `melee_start`）：

| 攻擊者 | 被攻擊者 | 結果 |
|-------|---------|------|
| 輕/重攻擊 | 也在輕/重攻擊（weapons 碰撞） | **雙方卡刀**（播放命中裝甲動畫，雙方均不扣血） |
| 重攻擊 | 在輕攻擊（碰撞） | 輕攻擊方卡刀，重攻擊方**不卡** |
| 輕攻擊 | 在重攻擊（碰撞） | 輕攻擊方卡刀，重攻擊方不卡 |
| 任意攻擊 | 未攻擊（格擋或空手） | 正常進入格擋/傷害判斷 |

「卡刀」效果對應撞到裝甲時的 `hit_stop` 動畫（`play_hit_animations` with `armor_type = 2`）。

---

### 系統 5：蓄力階段可被輕擊打斷

#### 原本機制分析
`player_character_state_helper.lua` L1238 中：
```lua
uninterruptible_heavy = ActionUtils.is_melee_start_sub_action(current_action_settings) and buff_extension:has_buff_perk("uninterruptible_heavy")
```
- `melee_start` 階段（續力）：若沒有 `uninterruptible_heavy` 天賦，**已可被打斷**。
- `sweep` 階段（揮舞）：動作有 `uninterruptible = true` 時不可打斷。

因此，**蓄力階段可被打斷**這個需求，在大多數情況下已由原本機制支援，只要傷害能正常觸發 `hitreact_interrupt()`。

**需要確認**：PVP 傷害是否會正確觸發 `recently_damaged()` 與 `hitreact_interrupt()`，若有需要則 Hook 。

> **天劫難度的友軍傷害乘數**：「天劫難度的友軍傷害計算方式」指的是 Cataclysm 難度的 `friendly_fire_multiplier`。實際數值需從難度設定表確認，或使用固定值（如 0.5）。請確認要使用哪個難度的友軍傷害乘數，或設定一個固定的 PVP 傷害比例。

> [!IMPORTANT]
> **雙手武器判斷標準**：「雙手武器的重擊」如何判斷？是根據武器模板的某個欄位（如 `two_handed`），還是根據武器分類（如 2h_sword、greatsword 等）？

> [!NOTE]
> **網路同步**：PVP 傷害的網路同步是否需要特別處理？原遊戲有完整的 RPC 機制，Hook 後應可複用。

### 系統 3：完美格擋/推擊踉蹌（新增）

#### [NEW] `pvp_stagger.lua`
- 當 `is_timed_block = true` 時（完美格擋），對攻擊者觸發 3 秒踉蹌。
- 當推擊命中玩家時，觸發 1 秒踉蹌。
- 踉蹌使用 `StatusUtils.set_overpowered_network()`。
- **防疊加**：連續推擊踉蹌時間若仍有效，不延長（最多 1 秒）。
- 踉蹌期間玩家無法進行格擋（因為 `overpowered` 狀態會停止武器動作）。

**所需 Overpowered 模板**（新增）：
```lua
-- 3 秒完美格擋踉蹌
pvp_parry_stagger = { duration = 3, ... }
-- 1 秒推擊踉蹌  
pvp_push_stagger = { duration = 1, ... }
```

### 系統 4：武器碰撞卡刀（新增）

#### [NEW] `pvp_weapon_clash.lua`
實作邏輯：在 `action_sweep.lua` 的命中處理中，在確認傷害之前，額外檢查目標玩家是否也正在進行攻擊（`current_action_settings.kind == "sweep"` 或 `melee_start`）：

| 攻擊者 | 被攻擊者 | 結果 |
|-------|---------|------|
| 輕/重攻擊 | 也在輕/重攻擊（weapons 碰撞） | **雙方卡刀**（播放命中裝甲動畫，雙方均不扣血） |
| 重攻擊 | 在輕攻擊（碰撞） | 輕攻擊方卡刀，重攻擊方**不卡** |
| 輕攻擊 | 在重攻擊（碰撞） | 輕攻擊方卡刀，重攻擊方不卡 |
| 任意攻擊 | 未攻擊（格擋或空手） | 正常進入格擋/傷害判斷 |

「卡刀」效果對應撞到裝甲時的 `hit_stop` 動畫（`play_hit_animations` with `armor_type = 2`）。

### 系統 5：蓄力階段可被輕擊打斷

#### 原本機制分析
`player_character_state_helper.lua` L1238 中：
```lua
uninterruptible_heavy = ActionUtils.is_melee_start_sub_action(current_action_settings) and buff_extension:has_buff_perk("uninterruptible_heavy")
```
- `melee_start` 階段（續力）：若沒有 `uninterruptible_heavy` 天賦，**已可被打斷**。
- `sweep` 階段（揮舞）：動作有 `uninterruptible = true` 時不可打斷。

因此，**蓄力階段可被打斷**這個需求，在大多數情況下已由原本機制支援，只要傷害能正常觸發 `hitreact_interrupt()`。

**需要確認**：PVP 傷害是否會正確觸發 `recently_damaged()` 與 `hitreact_interrupt()`，若有需要則 Hook 。

2. 單手／雙手武器判定
VT2 原生 Slayer 天賦已確認使用：
inventory_extension:get_item_template(slot_data)
取得 weapon template，再讀取：
weapon_template.buff_type
分類：
MELEE_1H → 單手
MELEE_2H → 雙手
因此 PVP：
不建立武器名稱白名單。
不自行猜測其他武器欄位。
所有 PVP 的單手／雙手判定統一使用這套原生 weapon_template.buff_type 邏輯。
下一步只需要確認目前攻擊 action 如何取得對應的 weapon template。
